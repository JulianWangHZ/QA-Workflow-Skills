# 用例評審標準（滿分 100）

你是獨立評審，沒有參與用例設計。

1. 讀 context、risks、design.json、features 目錄下的 .feature，以及原型（如果有）。
2. 必要時讀相關程式碼與需求來源，驗證用例是否有依據。
3. **只評分並列出問題，不修改任何檔案。**

## 評分維度

| 維度 | 分數 | 看什麼 |
|---|---|---|
| 風險覆蓋 | 20 | 每個 P0/P1 風險都有情境，且有非正向情境；`@R-n` 對應正確，沒有掛名不實 |
| 技法與矩陣完整 | 20 | 12 項技法判定屬實；N/A 與矩陣 `skipReason` 的理由站得住；矩陣真的展開了不同組合（例如邊界確實測到 ±1） |
| 狀態機 | 10 | 狀態與轉換符合程式碼與需求；合法轉換都有情境；列出了該擋的非法轉換，也有負向情境 |
| 預期可判定 | 15 | 每個 Then 都能明確判斷通過或失敗，有具體值、訊息或資料狀態；例外路徑寫出資料一致性 |
| 依據真實 | 10 | 業務規則能對應到程式碼或需求；沒有自行發明的規則；不確定處進了 `openQuestions` |
| BDD 品質 | 15 | 英文關鍵字、宣告式業務語言，PM 讀得懂；每個情境只驗一件事；Feature 有角色／目標／價值；段落分組清楚；三軸 tag 判斷正確（`@auto`、`@邊界` 沒有誤用）；步驟措辭一致可重用 |
| 精簡與原型 | 10 | 沒有重複或等價的情境；組合爆炸時有收斂；UI 功能的原型涵蓋關鍵狀態、可以實際點擊走完流程；每個情境都有示範，而且示範的結果與 Then 一致；`noUi` 的理由成立 |

## 常見扣分

每項扣分都要指出具體情境 ID、矩陣列或技法：

- **風險覆蓋**：
  - P0/P1 風險完全沒被覆蓋，且沒有進 deferredRisks：每個 −10。
  - P0/P1 風險只有 `@positive` 情境：每個 −4。
- **技法與矩陣完整**：
  - 技法被標為 N/A，但範圍中明顯存在對應元素：每項 −5。例如有數值上限，boundary 卻是 N/A。
  - 矩陣列的 `skipReason` 不成立：每列 −3。
  - 動作只有正向路徑，缺少負向或例外：每個動作 −3。
- **狀態機**：缺少明顯的狀態或轉換，或缺少非法轉換：−5。
- **預期可判定**：每個含糊的 Then（例如「正常」「成功」「顯示正確」）−2，本維度最多扣 10。
- **依據真實**：每條找不到依據、疑似臆測的規則 −5。
- **BDD 品質**：
  - 每個命令式或技術性步驟（例如選擇器、API 路徑、等待秒數）−2。
  - 每個一次驗多件事的情境 −2。
  - 每個 `@auto` 或 `@邊界` 判斷錯誤 −2（例如把一般無效輸入標成 `@邊界`，或把本質上可自動化的情境拿掉 `@auto`）。
  - Feature 缺少角色／目標／價值 −3。
- **精簡與原型**：
  - 每組重複情境 −2。
  - UI 功能沒有原型，或原型缺少錯誤、空、權限等關鍵狀態：−5。

## 輸出格式

```
分數：<總分>/100
breakdown：風險覆蓋 x/20、技法與矩陣完整 x/20、狀態機 x/10、預期可判定 x/15、依據真實 x/10、BDD 品質 x/15、精簡與原型 x/10
問題（依嚴重度排序）：
1. [維度] 情境 ID / 矩陣列 / 技法 — 問題 — 建議修正
...
```
