# 12 種測試設計技法

`design.json` 的 `coverage.techniques` 必須包含下表全部 12 項（`technique` 欄位填英文 ID）。
大多數技法的展開結果寫成 `matrices` 中的一張矩陣，每一列對應情境或寫明不測理由。
每項只有兩種結果：

1. 適用：產出用例，並列出用例 ID。
2. 不適用：寫出具體理由。

| ID | 技法 | 一句話 |
|---|---|---|
| `equivalence` | 等價類劃分 | 每個輸入切成有效類與無效類，每類取一個代表值 |
| `boundary` | 邊界值分析 | 每個門檻測「剛好、少一點、多一點」 |
| `decision-table` | 決策表 | 多個條件的組合，每種組合對應一個結果 |
| `path` | 正向／負向／例外路徑 | 每個動作都有成功、被規則擋下、系統出錯三條路 |
| `state-transition` | 狀態轉換 | 每條合法轉換都走過，非法轉換要被擋下 |
| `role-permission` | 角色與權限 | 同一功能對每種角色（含未登入）的預期 |
| `data-lifecycle` | 資料生命週期 | 新增、讀取、修改、刪除，加上空、首筆、大量 |
| `pairwise` | 成對組合 | 因子多時，用成對組合收斂成代表性組合 |
| `error-guessing` | 錯誤猜測 | 依經驗補上常見出錯情境 |
| `concurrency` | 併發與重複操作 | 重複送出、同時操作、重試造成的重複效果 |
| `dependency-failure` | 外部依賴失效 | 第三方服務、資料庫、網路失敗或變慢 |
| `environment` | 環境與設定差異 | feature flag、設定、地區、裝置造成的行為差異 |

---

## equivalence — 等價類劃分

- **做法**：
  1. 對每個輸入欄位或參數，列出有效類與無效類。
  2. 每類只取一個代表值。
  3. 無效類要一類一個用例，不要把多個無效值塞進同一個用例，否則無法判斷是哪一個被擋下。
- **適用**：有輸入欄位、參數、選項、身分類別。
- **可判 N/A**：完全沒有輸入的純展示行為。
- **例**：
  - 手機號碼：有效（10 碼數字）；無效（9 碼、11 碼、含字母、空白、空字串）。

## boundary — 邊界值分析

- **做法**：
  1. 找出每個有順序的門檻：數值、長度、日期、時間、額度、次數。
  2. 每個門檻測「剛好在邊界」「邊界內側一格」「邊界外側一格」。
- **適用**：任何上限、下限、期限、冷卻時間、分頁大小。
- **可判 N/A**：輸入沒有順序（只有類別）。
- **例**：
  - 需提前 24 小時取消：測 24:00、23:59、24:01。
  - 名稱長度上限 50：測 49、50、51。

## decision-table — 決策表

- **做法**：
  1. 把影響同一結果的條件列成決策表矩陣，每種組合對應一個結果。
  2. 結果相同且條件可合併的列可以合併，但要能說明合併理由。
- **適用**：資格判定、價格與折扣計算、多條件開關。
- **可判 N/A**：結果只由單一條件決定。
- **例**：

  | 會員 | 金額 ≥ 1000 | 優惠券 | 結果 |
  |---|---|---|---|
  | 是 | 是 | 無 | 免運 |
  | 否 | 是 | 無 | 收運費 |
  | 否 | 否 | 免運券 | 免運 |

## path — 正向／負向／例外路徑

- **做法**：每個會改變資料或觸發動作的操作，至少三條路：
  1. **正向**：成功完成。
  2. **負向**：業務規則擋下。例如餘額不足、資格不符、重複資料。
  3. **例外**：系統層錯誤。例如逾時、服務錯誤、資料不存在。
- **例外路徑的預期**：必須寫出使用者看到什麼，以及資料是否保持一致（例如不會扣款、不會產生半筆訂單）。
- **適用**：所有可提交、可觸發的動作。**這是最常被漏掉的一項。**
- **可判 N/A**：幾乎不會。純讀取的畫面也有「無資料」「載入失敗」兩條負向路徑。

## state-transition — 狀態轉換

- **做法**：
  1. 在 `stateMachine` 列出所有狀態與轉換。
  2. 每條合法轉換至少一個用例。
  3. 列出不該發生的轉換（`valid: false`），驗證系統會拒絕。
  4. 有時效的狀態（試用到期、鎖定解除）要測時間到之前與之後。
- **適用**：訂單、審核、訂閱、帳號鎖定等會隨操作或時間改變的狀態。
- **可判 N/A**：單次操作，前後沒有狀態差異。

## role-permission — 角色與權限

- **做法**：
  1. 對每個角色（含未登入、已停用帳號）列出能否看到、能否操作。
  2. 越權情境至少各一個用例：
     - 水平越權：看到或修改別人的資料。
     - 垂直越權：做了更高權限才能做的事。
- **適用**：多角色系統、有擁有者概念的資料。
- **可判 N/A**：只有單一角色，而且沒有「別人的資料」。

## data-lifecycle — 資料生命週期

- **做法**：
  1. 對每個會被保存的資料物件，檢查新增、讀取、修改、刪除是否都被覆蓋。
  2. 補上**空狀態**、**第一筆**、**大量資料**（分頁、上限）。
  3. 補上**刪除後的影響**：關聯資料、軟刪除後是否仍被引用。
- **適用**：可增刪改查的清單或資料。
- **可判 N/A**：只觸發動作，不保存資料。

## pairwise — 成對組合

- **做法**：
  1. 有 3 個以上互相獨立、各有多個值的因子，而且全組合太多時使用。
  2. 選出讓「任兩個因子的每種值組合」至少出現一次的最小集合。
  3. 在矩陣的 `description` 說明收斂前後的數量。
- **適用**：瀏覽器 × 語系 × 方案 × 付款方式這類組合。
- **可判 N/A**：因子少於 3 個，或用決策表就能完整列出。

## error-guessing — 錯誤猜測

逐項想一遍，適用的就寫成用例：

- **連續操作**：連點兩次送出、送出後立刻返回上一頁、重新整理。
- **特殊輸入**：前後空白、emoji、超長字串、HTML/SQL 特殊字元、全形與半形。
- **時間**：跨日、跨月、閏年、時區、夏令時間、伺服器與客戶端時間不一致。
- **數值**：0、負數、小數精度、四捨五入、幣別。
- **流程中斷**：操作到一半關閉頁面、網路中斷後恢復、Session 過期。

- **可判 N/A**：極簡的靜態內容。

## concurrency — 併發與重複操作

- **做法**：驗證同一資源被同時或重複操作時，結果仍然正確：
  1. **冪等性**：同一請求送兩次，只生效一次。
  2. **競態**：兩人同時搶最後一個名額，只能有一人成功。
  3. **重試**：逾時後重試，不會重複扣款或重複建立。
- **適用**：扣庫存、扣款、搶名額、計數器、任何「只能發生一次」的動作。
- **可判 N/A**：純讀取，或資源不可能被同時操作。

## dependency-failure — 外部依賴失效

- **做法**：對每個外部依賴（第三方 API、付款、簡訊、郵件、檔案儲存、資料庫），測以下狀況時系統的行為，以及資料是否保持一致：
  - 失敗
  - 逾時
  - 回傳非預期格式
  - 延遲回呼
- **適用**：流程中有任何外部呼叫。
- **可判 N/A**：完全不依賴外部系統。

## environment — 環境與設定差異

- **做法**：列出會改變行為的設定，每種值至少一個用例：
  - feature flag
  - 環境變數
  - 地區與語系
  - 裝置與瀏覽器
  - 方案等級
- **適用**：有 flag、灰度發佈、多地區、多方案。
- **可判 N/A**：所有環境行為一致，而且沒有可切換的設定。

---

## 非功能需求

效能、無障礙、資安掃描這類需求，要能寫出**可判定的預期**才寫成用例，例如「列表 API 在 1000 筆資料下 p95 < 500ms」。
寫不出可判定的預期時，放進 `openQuestions`，註明建議另外安排的測試，不要硬寫成模糊的用例。
