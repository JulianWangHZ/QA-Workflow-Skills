# Healer 與防假綠檢查

## Healer：只修失敗的測試

1. **打開實際畫面**：用 Playwright MCP 或 Appium MCP，走到失敗的那一步，看當下的畫面與元素。
   - 同時參考 trace、截圖與 log，但**新的 locator 一定要在實際畫面上驗證過**。
   - 工具不能用時，不要猜著改：回傳 `needs-user`，請使用者先設定好 MCP。
2. **判斷根本原因**，對照 `../SKILL.md` 的四種分類：
   - **測試缺陷**，例如 locator 改了、等待條件錯了、資料沒準備好 → 修正。
   - **產品缺陷**：畫面行為和已確認的 Then 不一致 → **停手**，記錄為產品缺陷，不修改斷言。
   - **環境問題**、**需求不明** → 依分類處理。
3. **修正範圍**：
   - 只修 Page Object、step、fixture、測試資料。
   - 新的 locator 要實際驗證過，並補進證據圖。
   - 不能用 `waitForTimeout`、`test.fixme()` 或 skip 蓋掉問題。
4. **每個失敗的測試最多修 `run.maxHealRounds` 輪**（預設 2）。一輪包含一次診斷修正加一次重跑。
   - 修到上限還是失敗 → 停手，回報你判斷的根本原因。
5. **只重跑受影響的測試**，已經通過的不用重跑。修到共用的 Page Object 或 step 時，才補跑受影響的範圍。
6. 修過的測試要重新做防假綠檢查。

## 防假綠檢查（oracle audit）

**測試通過，不代表斷言是對的。** 每個通過的 task 都要證明：它的斷言在結果錯誤時會失敗。

1. **對齊檢查**：比對 step 中的斷言與證據圖的 oracle。斷言必須驗證證據圖記錄的那個結果，不能換成比較寬鬆的版本。例如：
   - 應該驗證訂單狀態，卻只驗證頁面出現了某個字。
   - 應該驗證清單多了一筆，卻只驗證沒有錯誤。
2. **突變檢查**：每個 task 挑一條關鍵斷言：
   1. 暫時把它改壞，例如反轉條件或改掉期望值。
   2. **只跑這一個測試**，它必須失敗。
   3. **立即還原**，不需要再重跑。
   - 斷言在共用的 step 或 Page Object 中時，突變期間只跑這一個測試，避免影響其他測試。
3. **記錄**到 `results.json` 的 `oracleAudit`：`{ taskId, mutation: "改了什麼", turnedRed: true | false, log }`。
   - `turnedRed: false` 代表假綠：修正斷言，然後重新檢查。`qa gate run` 會擋下沒做檢查或假綠的 task。
4. 設定 `run.oracleAudit: false` 可以關閉這項檢查，只建議在特殊情況下使用，並在回報中說明原因。
